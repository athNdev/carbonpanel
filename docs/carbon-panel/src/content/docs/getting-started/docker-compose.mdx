## Prerequisites

Carbon Panel manages Minecraft servers as Docker containers, so Docker is required.

- [Docker Engine](https://docs.docker.com/engine/install/) with Docker Compose

## Compose file

The recommended way to run Carbon Panel. Create a `docker-compose.yml` or use the one from the repo:

Spin up your service:

```bash
docker compose up -d
```

## Volume paths

Carbon Panel creates a Docker bind mount for each managed Minecraft server, and the Docker daemon interprets those paths on the host, not inside the panel's container.

There is nothing to configure for this. At startup the panel reads the mount table of its own container and works out the host path behind `/app/data`. Your compose file is the only place that mapping exists:

```yaml
volumes:
  - /srv/minecraft/data:/app/data
```

With that entry, a server directory the panel sees at `/app/data/servers/x` is requested from the daemon as `/srv/minecraft/data/servers/x`.

Startup validates the mapping before anything writes to it. It stops with a message naming the directory when:

- no volume is mounted at the data directory (worlds would land in the container's own filesystem and disappear on recreate),
- the volume is mounted read-only,
- the data directory is a `tmpfs`,
- the container user cannot write to it (`no write permission on the mount dir`),
- a `CARBONPANEL_HOST_DATA_PATH` override is set to a relative path (`mount path should be absolute`).

`CARBONPANEL_HOST_DATA_PATH` and `CARBONPANEL_DATA_DIR` are no longer needed. Both are still read for backwards compatibility when the panel cannot read its own mount table (for example behind a Docker socket proxy that forbids container reads), and setting `CARBONPANEL_HOST_DATA_PATH` is reported in the log as deprecated.

:::caution[SELinux]
On Fedora, RHEL, CentOS, etc., append `:z` to volume mounts:
```yaml
- /var/run/docker.sock:/var/run/docker.sock:z
```
:::

Once running, open **http://\<your-host\>:8080** and create your admin account.
