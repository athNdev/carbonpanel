## Prerequisites

Carbon Panel manages Minecraft servers as Docker containers, so Docker is required both at build time and runtime.

- **Go** at the version declared by `go.mod`
- **Bun** at the version recorded in `toolchain-versions.json`
- **Docker** (also used to run [buf](https://buf.build/) for protobuf code generation)
- **Make**

## Build steps

```bash
# Clone the repo
git clone https://github.com/athNdev/carbon-panel.git
cd carbon-panel

# Install the pinned frontend dependencies used to format generated code
cd web/carbon-panel && bun install --frozen-lockfile && cd ../..

# Generate protobuf code (Go + TypeScript) via Docker buf, then build frontend
make gen
cd web/carbon-panel && bun run build && cd ../..

# Build the Go binary with embedded frontend
go build -o carbon-panel ./cmd/carbon-panel
```

The `//go:embed` directives bake the frontend build into the binary so it serves the UI without a separate web server.

The container build defaults to the Go, Bun and Buf versions recorded in
`toolchain-versions.json`. Operators can explicitly select compatible images
using the `GO_IMAGE`, `BUN_IMAGE` and `BUF_IMAGE` Docker build arguments.
Version tags are not immutable digests; use digest-pinned image references when
your deployment requires immutable inputs.

## Live Development (Hot Reloading)

For active development with live reload for both backend and frontend:

```bash
# Using Bun (Recommended):
bun run dev

# Or using Make:
make dev

# Or Windows (PowerShell):
.\scripts\dev.ps1

# Or Linux/macOS (Bash):
./scripts/dev.sh
```

- **Frontend (Vite HMR)**: `http://localhost:5174`
- **Backend API**: `http://localhost:8080`

The development profile binds to loopback by default. Select `bun run dev --lan`
explicitly to expose development listeners to the LAN. Ctrl+C stops only the
process trees owned by that session; a child failure stops its peer.

## Running

```bash
# Using default config (./config.yaml if it exists, otherwise defaults)
./carbon-panel

# Or point to a specific config file
./carbon-panel -config /path/to/config.yaml
```

All config options can also be set via environment variables with the `CARBONPANEL_` prefix. For example, `server.port` becomes `CARBONPANEL_SERVER_PORT`. Environment variables take precedence over the config file.

:::tip[Host path mapping]
When running the binary directly on a host (not in a Docker container), no path translation is needed: the Docker daemon sees the same filesystem the panel does, and the directories are used as-is. `CARBONPANEL_DATA_DIR` and `CARBONPANEL_HOST_DATA_PATH` are legacy overrides and are not required.

To change where Carbon Panel stores its database and server data, set `CARBONPANEL_STORAGE_DATA_DIR` or configure it in your config file:

```yaml
storage:
  data_dir: /your/path  # Default: ./data (relative to working directory)
```
:::

For all available configuration options, see [Configuration](/configuration/).
