This guide uses Carbon Panel's first-party installer script to deploy the **Carbon Panel controller** inside an **existing** Linux guest (Proxmox LXC or VM). It does **not** provision a Proxmox host, create the guest, or change host security settings. You prepare and secure the guest yourself, then run the script inside it.

## Prerequisites

- A [Proxmox VE](https://www.proxmox.com/en/proxmox-virtual-environment/overview) host where you can create and manage a guest
- An existing Debian or Ubuntu LXC/VM (or another compatible Linux guest) with:
  - [Docker Engine](https://docs.docker.com/engine/install/) and Docker Compose v2 (`docker compose`)
  - Network access to pull `atharvnaphade/carbonpanel` images
  - Persistent storage for `/opt/carbon-panel` (or your chosen install directory)
  - Permission to run Docker commands (typically root or a user in the `docker` group)

:::note[Docker inside LXC]
Running Docker inside an LXC depends on your Proxmox/LXC configuration and kernel features. Carbon Panel does not require or apply privileged LXC settings, nesting changes, or AppArmor/seccomp relaxations. Use a guest configuration that meets your security requirements and supports Docker.
:::

:::caution[Guest-local Docker socket]
The generated `compose.yml` mounts `/var/run/docker.sock` because Carbon Panel manages Minecraft server containers through the guest-local Docker daemon. Control of the panel container therefore implies control of Docker on that guest. Keep the panel on a trusted network, set strong credentials, and treat the guest as dedicated to Carbon Panel.
:::

## Install (inspect, then run)

Run these commands **inside the guest**, not on the Proxmox host shell. Download the script, inspect it, then run it:

```bash
curl -fsSLO https://raw.githubusercontent.com/athNdev/carbonpanel/main/scripts/proxmox/install-carbon-panel.sh
less install-carbon-panel.sh
sudo bash install-carbon-panel.sh
```

By default the script:

- Installs to `/opt/carbon-panel`
- Creates `data`, `backups`, and `tmp` directories if they do not exist
- Writes `compose.yml` **only if it does not already exist** (existing compose/config are preserved)
- Uses the shipped controller image `atharvnaphade/carbonpanel:latest` with host networking and bind mounts for `/app/data`, `/app/backups`, and `/app/tmp`
- Pulls the image and starts the `carbon-panel` container with `docker compose pull` then `docker compose up -d`

Once complete, Carbon Panel is accessible at **http://\<guest-ip\>:8080** (default port).

To use a different install directory or image:

```bash
sudo bash install-carbon-panel.sh --dir /srv/carbon-panel --image atharvnaphade/carbonpanel:latest
```

## Update

To update the controller while preserving existing deployment data, compose customizations, and config, run in the guest from the directory that holds the script:

```bash
curl -fsSLO https://raw.githubusercontent.com/athNdev/carbonpanel/main/scripts/proxmox/install-carbon-panel.sh
less install-carbon-panel.sh
sudo bash install-carbon-panel.sh update --dir /opt/carbon-panel
```

`--dir` defaults to `/opt/carbon-panel` (or `$CARBON_PANEL_DIR`), so you can omit it if you used the default install directory. You can also re-download and inspect the script before running `update`.

The update path pulls the selected image and recreates the container (`docker compose pull && docker compose up -d`) without deleting bind-mounted data, backups, or tmp files. Before upgrading, consider a controller database snapshot as described in [Docker Compose](/getting-started/docker-compose/).

## Existing deployments and data

- **Preserved:** `data/`, `backups/`, `tmp/`, and any existing `compose.yml` or `config.yaml` in the install directory.
- **Not overwritten:** re-running `install` leaves an existing `compose.yml` unchanged.
- **Not touched:** this script does not delete Docker volumes or bind mounts, and does not modify Proxmox host configuration.

If you previously used the third-party Proxmox VE Community Scripts helper, your existing container/data remain where that helper placed them. This first-party script is a supported path for **existing prepared guests** and for future installs you manage with this repository's script; it does not provide the community helper's `update` console alias.

## Sizing guidance

**CPU** — A single Minecraft server (vanilla or modded) rarely exceeds 400% (4 cores). While up to 4 cores per server is recommended for optimal performance, you can start with 4 cores and increase as needed.

**RAM** — Vanilla servers may only need a few GB, but heavily modded servers average 10 GB+ per instance, especially with multiple players. Size the guest for the panel plus the Minecraft servers you plan to run.

**Disk** — Depends on what you plan to run and for how long. 40–80 GB is a reasonable starting point for a small setup and can be expanded later.

For all available configuration options, see [Configuration](/configuration/).
